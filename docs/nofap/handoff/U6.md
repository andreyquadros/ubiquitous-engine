### Deviations from the design

- **`panic.crisis` is not a key of the namespace map.** Its Portuguese and English texts have
  different placeholders (`{crisis_chat}`, `{emergency_phone}` against `{intl_directory}`), and
  `src/i18n/parity.test.ts`, which I do not own, requires equal placeholders per key. The two exact
  strings are the named export `PANIC_CRISIS` of `i18n/messages/nofap.ts`, rendered by
  `crisisText(locale, resources)`. `t('nofap.panic.crisis')` therefore does not resolve. If the
  integrator prefers an exemption in the parity test, moving the two strings into the map is a
  two-line change.
- **The fixtures are checked through `golden.ts`, not `satisfies` on the JSON imports**
  (integrator decision 13). `fixtures.test.tsx` additionally asserts that the two JSON files equal
  the typed module.
- **The wizard does not call `system_preview`.** The command takes no arguments, so before
  `enable` it can only describe the stored (empty) choice, and 11.3 wants nothing called before
  the last step. Step 2 lists the changes from the wizard's own choices in general words
  (`wizard.change.*`: no count of sites, no current DNS servers). The exact list from
  `system_preview` is shown in the "Aplicar" dialog, before `system_apply`.
- **Display name "NoFap"** (integrator decision 1). No string contains it: the name always comes
  from `view.display_name` through `{name}`, and the naming test fails on the literal in any value.
- **The card window asks for its own size** (`cardSize` in `labels.ts`: 420×132, 160, 200, 220,
  560) with `getCurrentWindow().setSize`, in a try/catch. The design's capability list for
  `shield-card` has no set-size permission. See the note for U7.
- **"Abrir apoio" is rendered in the same window**, from the same card: the page switches to the
  support view locally and picks one of `block.breathe`, `block.choice`, `block.next` by the card
  id. It does not wait for the engine to send a second card.
- **Help resources are plain text**, not links: the webview opens nothing itself, so the CSP test
  stays as it is. Phone numbers and addresses come only from the `support` payload.
- **The DNS tier is a two-way choice**, "Cloudflare for Families (1.1.1.3)" or "Só a lista neste
  computador" (the wording `dns.disclosure` points to), not a switch.
- **With a delay of 0** the page's own dialog ("Desligar o NoFap?", primary button "Manter
  proteção") is the confirmation, not the focus guard's `DisableWarnings` component: the page then
  sends `request` and, because the pending request comes back ready, `confirm_pending` at once.
- **Sidebar.** The entry appears only after `view` has answered, because its label is the display
  name. If the command fails (a shell without the module), there is no entry.
- **Not built:** "Modo estrito" for mixed platforms (6.1 mentions it as an add/remove of a host;
  the lists already do that) and "Verificar agora" (integrator decision 14). The caps editor was
  missing here and was added by the review.
- **A component beyond 7.9's list:** `ResolverChoice`, `SampleFrameView`, and the three files of
  `tabs/`.

### Contract notes for the units that come after

**U5 (engine service, `ipc::handle`)**
- Request shape: one argument named `command` holding `{ cmd, args? }`.
- Errors: the page shows `IpcError.message` in a toast. The mock throws `invalid: …` (enable
  without `self_use`, vision without consent, `system_remove` or `reset` while on, confirming a
  request that is still waiting) and `not_found: …` (unknown pending id).
- `enable` may or may not raise the OS prompt: the page handles both. A chosen tier that comes
  back `not_applied` shows "Proteção parcial" with an "Aplicar" button (preview, then
  `system_apply`).
- `request` returning `{ pending }` with `ready: true` (delay 0) is confirmed at once by the page
  when the change is `disable`; for any other kind the banner offers "Confirmar".
- `PendingView.remaining_secs` is counted down locally; at zero the page calls `view` again. The
  banner shows "Desligar"/"Confirmar" only when `ready` is true.
- The page names the site of a waiting `add_allow` or `remove_block` from `config.pending`
  (and `sites` for the id). A card never can.
- Card buttons: the window calls `card_action { id, action }` for **every** button first, then
  runs the flow itself. It also calls `record` for the flows (`surf_started`, `surf_done`,
  `step_away`). So `card_action` with `surf` or `support` must not count `surf_started` or
  `panic` again.
- After `not_it` the window calls `view` and compares the pending ids from before: a new
  `add_allow` shows `notit.request` with the current delay, otherwise `notit.snoozed`. Create the
  delayed request inside `card_action` (not later) for that to be right.
- After `request_exception` it shows `notit.request`; after `add_to_list`, "Adicionado à sua
  lista."; after `ok`, `later`, `close_window`, `restore`, `restore_network`, `keep_protection`
  and `turn_off` it closes the window.
- The `help` action: on a `reminder` card the window shows how to turn the module off; on any
  other card it shows `help.how`, the resources and `help.limits`. Nothing is asked of the shell.
- A `blocked` card with `discreet: false` opens directly as the support card (the four support
  buttons). `not_it` and `request_exception` in its `actions` are still shown there; other
  actions are not.
- `message_key` and `note_key` are looked up as `nofap.<key>` with `{name}` and `{delay}` filled
  in. A key the frontend does not have shows `block.discreet`.
- `support.resources`: the crisis sentence needs the ids `cvv` (with a phone), `samu` and, for
  English, `findahelpline`. Without them the window shows the list only, or "A lista de contatos
  de apoio não veio nesta versão do app." when the list is empty (`resources.json` is `[]`
  today).
- Events the page uses: `status` (patches the status; a different `overall` makes it read `view`
  again), `pending_changed` (reads `view`), `sites_changed` (reads `sites`). The card window
  uses `card` (shows the new card) and `card_closed` (closes when the id is its own).
