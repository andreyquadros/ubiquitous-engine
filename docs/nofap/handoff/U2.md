**How the tests were checked.** 29 hand-made mutations of the decision code (dropping the
observed-time rule, the caps, the never-block check, the gate check, the argument budget, the
orphan handling of the splice and others) were run against the unit tests. 27 failed a test or
did not compile. One showed a missing case and led to a fix (a restored network was judged by
what the machine still showed). One cannot fail while every gate entry is `false`
(`Gate::new` dropping a tier the table already opens).

**The hosts splice.** Defined for every input, also damaged ones (module documentation of
`hosts.rs`). Property tests with a hand-rolled generator (two over 1,500 generated files, two
over 300): LF, CRLF and mixed
endings, with and without a final line break, a lone carriage return at the end, a byte-order
mark, lines of up to 65,000 bytes, bytes that are not UTF-8, NUL bytes, foreign blocks with
similar markers, single `0.0.0.0` lines. Shown for files without a block: the file is a prefix
of the result, splicing twice changes nothing, and removing gives back the file byte for byte.
Shown for files that hold a block (whole, edited inside, END deleted, BEGIN damaged): everything
before and after is byte-exact after a replace and after a removal.

### Deviations from the design

**hosts.rs**
- `is_valid_hostname` is stricter than "ASCII letters, digits, hyphen, dots": lower case only (one
  spelling reaches the file, and the never-block rules are asked about that spelling); a numeric
  last label, decimal or `0x` hexadecimal, is an IP literal and refused; names that stay on the
  machine or the local network are refused (`localhost`, `.local`, `.localdomain`, `.lan`,
  `.internal`, `.home.arpa`, `.test`, `.corp`), because pointing them at the null address could
  break local services and the in-app guard never blocks them either.
- `names_for`: the cap counts every name of the block (canary, user names, twins, tier), not the
  tier names alone. On macOS and Linux the block holds the canary and 19,999 tier names.
- `render_block` leaves out any name with a character outside `a-z 0-9 - .`, whatever it is handed.
- `splice`: a text that is not a BEGIN line, lines without a marker and an END line is refused (the
  file comes back unchanged). A block whose END line is gone is recognised by its BEGIN line plus
  the lines only `render_block` produces (the hint, then pairs of a `0.0.0.0` and a `::` line with
  the same names), and the same backwards for a block whose BEGIN line is gone. More than one block:
  the first is replaced, the others removed. A block that closes a file without a final line break
  owns the line break in front of it.
- `inspect`: `Changed` also for a lone END marker and for more than one block (the seeded comment
  said `Absent` means "no BEGIN marker"); `Intact` also requires the declared number of names.
- New: `stamp_of(names) -> HostsStamp`, `LABEL_MAX_LEN`.

**plan.rs**
- `build_plan` leaves out, and counts in `extras_left_out`, the user sites the helper would refuse
  (not a public hostname, or under a never-block rule), not only those over the budget. One
  refused name would make the helper refuse the whole plan.
- An unknown owner or resolver is refused by `decode_plan` (`Malformed`), before `validate`.
- `validate` (through the new `admissible`) also refuses a name whose `www.` twin is under a
  never-block rule, because the helper writes the twin.
- `union` takes no names from an owner that does not want the hosts tier.
- `assess`, beyond the design's tables: a tier that is not chosen is `Applied` when the state file
  still lists it for this product and it is on the machine (switched off in the app, not yet
  removed), `InUseByOther` when it is there for the other product, `Off` otherwise. A chosen tier
  that is in place only for the other product is `InUseByOther`. Without a readable state file the
  tiers are judged by the machine alone. Resolver: `Missing` when the Linux drop-in is gone,
  `Changed` when interfaces differ; no active interface follows the state file; after "Restaurar
  minha rede" it is `NotApplied` whatever the machine shows (`InUseByOther` when the other product
  keeps it). Policies (the design gives rules, no table): `Applied`, `NotApplied`, `UpdatePending`
  (a browser installed since the last apply), `Changed`, `Missing` (every value we created is
  gone), `Unsupported { conflict | flatpak | unreadable }` when no browser is left to manage, and
  `Applied` with `Issue::PolicyAdvisoryOnly` on a Mac that has only Chromium-family browsers.
- `hosts_waiting` counts sites: a name and its `www.` twin are one.
- `preview` cannot know the gate (it has no such argument): the caller hands in the plan as sent
  (`without_gated`). "DNS goes back to automatic" is shown only when the state file listed a
  resolver and an interface is still ours.
- `build_plan`, `assess` and `preview` read the embedded never-block rules and hosts tier through
  `matcher::never_block()` and `list::hosts_tier()`; each has a twin that takes them as arguments
  (`build_plan_with`, `assess_with`, `preview_with`), which is what the unit tests use.
- New: `without_gated`, `admissible`, `owners_after`, `hosts_names`.

**commitment.rs**
- Everything is `Now` while the module is off, not only before the first enable.
- A change that asks for what is already so (switching off a tier that is off) is `Now`.
- `request` for a change that already waits returns the waiting entry; with a delay of 0 the entry
  is stamped ready at once and still needs `confirm`.
- `tick` brings a `ready_since` that lies in the future back to now (or clears it when the request
  is no longer ready), so the 24-hour window cannot be stretched by a clock change. `confirm`
  refuses a request that was ready for more than 24 hours.
- `apply_to_config(Disable)` also drops every waiting request; `SetResolver` clears
  `network_restored`. The `now` argument is not used.

**sampling.rs**
- `SampleCtx` gained `max_per_hour` and `max_per_day` (filled by `SampleCtx::new`): without them
  `decide` could not return `Skip::HourCap` or `Skip::DayCap`.
- `SampleEvent` gained `Unchanged`: without it a frame found unchanged would be captured again in
  every pass, because nothing recorded the look.
- `Allowed(Snooze)` is a candidate at signal cadence (U1b's note). A browser whose URL was read but
  has no verdict is treated as an unknown site.
- A messaging app keeps its own cadence whatever the signals; a media app with a signal is looked
  at at signal cadence.
- Relaxing: 60 minutes from the second `none`; after that the plain cadence, and relaxed again only
  after an answer other than `none` started a new run. A run of `none` answers is ended by any
  other answer, any failure and the heightened state. It is not ended by a title or path signal
  that came and went (during the signal the signal cadence applies).
- The cap of six checks per key per hour is lower than some rows of the cadence table allow (the
  relaxed 600 s cadence plus the two early checks); the cap wins.
- A `Positive` answer starts the heightened state by itself. A failed call and an unchanged frame
  are not counted against the caps. A key rejected three times gives `Skip::Degraded`.
- The re-check after "Não era isso" ignores the caps and the cadence, not a degraded provider.
- Every stored time is read against the longest duration it can have, so a clock set back cannot
  switch the check off for hours.

**Other modules**
- `resolvers::is_exactly` wants all four addresses and nothing else.
- `policies`: `same_value` treats `true`/`1` and `false`/`0` as equal (a registry has no boolean);
  `chromium_json(Firefox)` is `firefox_json()`; `conflicts` also names a browser whose observation
  carries `error: "conflict"` or a differing value in `foreign`. New: `display_name`,
  `FIREFOX_POLICY`, `FIREFOX_ENABLED`, `FIREFOX_LOCKED`.
- `gate::parse_override` ignores letter case and answers in the order of `Tier::ALL`; `Gate::new`
  keeps only tiers the table leaves closed.
- `state_dir::assess`: an owner or a mode that could not be read is `Reset` on Unix.
- `episode::PassConfirmer` stays confirmed for as long as the same host stays in front; a clock set
  back continues the running episode.
- `exclusions::reconcile`: an entry that leaves a list and returns waits again.
- `primary`: `decide` is the plain rule. "The standalone app wins a tie" is the new
  `decide_holding`, for a process that already holds the role.
- `messages`: the tray's status line is "{name}: ligado" / "{name}: on" (true whatever the status;
  "Proteção ativa" would be false when the status is reduced). The labels "Manter aberto", "Sair",
  "Abrir", "Verificar atualizações" exist only here; the frontend bank has no such keys.
- `help`: `resources.json` is embedded by `help.rs` itself, although `lib.rs` says only `list`
  reads embedded files (`list.rs` and `lib.rs` are not this unit's). `help_due` counts `quit_on`
  with the override requests (design 6.3). `forbidden_in` applies both lists to every text.
- `progress`: without an enabling day both numbers are 0; nothing is claimed about days the
  module did not see.

### Contract notes for the units that come after

**U4 (platform, the helper)**
- The names of the block: `plan::hosts_names(&owners, list::hosts_tier(), matcher::never_block(), os)`,
  then `hosts::render_block`, `hosts::splice`, and `hosts::stamp_of` for the state file. `assess`
  expects exactly that, so do not build the names another way. `hosts_names` re-validates the
  other owner's names from the state file (`plan::admissible`).
- Order in `apply`: `plan::decode_plan`, `plan::validate(&plan, never_block(), &gate)` with
  `PlanError::exit_code()`, then `plan::owners_after(state, &plan)` and `plan::union`.
- `splice` returns the file unchanged when handed something that is not a block; compare before
  writing. It never fails.
- `resolvers::is_exactly` is strict (four addresses). `plan::reset_targets` returns every
  interface that is exactly ours, active or not.
- `PolicyValue` keys for Firefox are `DNSOverHTTPS.Enabled` and `DNSOverHTTPS.Locked`
  (`policies::FIREFOX_ENABLED`, `FIREFOX_LOCKED`), whatever the back-end's own spelling. Values
  read from a registry may stay numbers. A Firefox `policies.json` that exists and is not ours:
  report `error: Some(reason::CONFLICT)`, or its values in `foreign`.
- `Gate::new(os, gate::parse_override(...))`; `gate.unverified_arg()` is the value for
  `--unverified`; `plan::without_gated(&plan, &gate)` is the plan to send and to preview.
- `state_dir::assess(&meta, os)`: `Absent` create, `Trusted` use, `Reset` remove without following
  a link and recreate (Unix), `Refuse` exit 4 (Windows).

**U5 (engine service)**
- `plan::assess`: put the last canary answer into observations that did not look (decision 11).
  When a quick Windows read failed (`resolver.error` set, `full == false`), keep the resolver part
  of the last full read instead. Record in `config.internal.previous_dns` every interface seen at
  apply, also those on automatic DNS (empty `servers`): an interface that is not listed there is
  "new" for `Issue::NewConnectionUnfiltered`.
- `commitment::tick(config, elapsed, now)`: `elapsed` is the real running time since the previous
  call, from a monotonic clock. Call it from the verify pass only; calling it from `view` with a
  constant would let a user speed the delay up by reloading the page. `request` may answer with an
  entry that already waited: count `override_request` only for a new one (its `id` is the one you
  passed). `apply_to_config(Disable)` empties `pending`.
- `sampling`: every pass `record(Front)` then `decide`. On `Capture`: take the frame; if
  `frame_unchanged` record `Unchanged` and send nothing; otherwise send and record `Checked` or
  `Failed`. A `Confirm` and its second frame are two `Checked` events. `SampleCtx::new` copies the
  caps; `ctx.local_signal()` is the argument for `refusal_card_due`. `record(Checked { Positive })`
  starts the heightened state; record `Heightened` yourself for a block and a bypass suspicion.
  "Não era isso" on a vision card: `record(NotIt)`; when the re-check is positive again,
  `record(NotItConfirmed)`. Call `memory.set_day_count` at start and `memory.clear()` when the
  provider or the key changes (that is what resets `key_rejected`). The monthly budget is not in
  this module.
- `primary::decide` before the first heartbeat, `primary::decide_holding` afterwards.
- `exclusions::reconcile` with the enabling instant when the module is enabled, then on every
  change of the lists; `effective` and `excludes` fill `SampleCtx::excluded`.
- `help::help_due(counts, last_shown, today)`; `help::resource_views()` for `support.resources`
  (ids `cvv`, `samu`, `caps`, `crp`, `findahelpline`, as the card window expects).
- `messages::rotation_key(discreet, user_list, n)` for `NofapCard.message_key`;
  `messages::notification_text` for the fallback notification.
- `progress::local_day_hour(now, offset)` is the key of a counter; `days_your_way` and `streak`
  take `since = enabled_at`'s local day.

**U7, U8 (shells)**

### Open points

- **Every gate entry is closed.** The code is ready for the gate-opening step; until then the
  product has no DNS-level blocking and the page must say "Em verificação neste sistema".
- **The help resources are unverified.** Phone numbers, addresses and notes come from the design
  and were not checked against the organisations' own pages.
- **`tests/embedded.rs` has its own copy of the hostname rule** (written while `hosts.rs` was a
  stub). It should call `hosts::is_valid_hostname`. I checked once, with a throwaway test that is
  not in the repository, that all 20,000 lines of `hosts-tier.txt` and the block canaries pass the
  real function and that none is under a never-block rule.
- **`lib.rs` says only `list` reads embedded files.** `help.rs` now embeds `resources.json`, and
  three functions of `plan.rs` reach the embedded data through `matcher` and `list`. The sentence
  needs the integrator's edit, or `list.rs` gets an accessor for the resources.
- **An adapter without IPv6.** `is_exactly` wants the IPv6 pair too. If Windows reports an adapter
  with IPv6 unbound as having only the two IPv4 servers, the tier reads `Changed` there. Only the
  Windows smoke run can tell; the gate is closed.
- **The exclusion delay does not defend against a clock set forward** (it has no observed-time
  rule like the commitment delay). An entry added to ubiqX's privacy lists becomes effective at
  once if the clock is moved ahead by the delay.
- **A clock set back before a request, then put right,** shortens a long delay to 15 minutes of
  running time. That is the design's stated limit (6.2), not something this unit could close.
- **Two blocks with one damaged marker each** (the END of the first and the BEGIN of the second
  deleted) read as one block, and user lines between them would go at the next write. It needs two
  blocks and two edits; the hint line in the file says what the markers mean.
- **The tray status line** names the module ("NoFap: ligado"). With the display name the owner
  chose, that is what the tray shows; a neutral wording would need a decision.
- **`Gate::new` dropping a tier the table opens** cannot be tested while every entry is `false`.
- CI: I did not look at any CI run for my pushes.
