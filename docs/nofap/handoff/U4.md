### Deviations from the design

**Shape of the module**
- 15 source files instead of the 7 of design 7.7, to keep every file under 400 lines:
  `shield.rs`, `converge.rs`, `hostsfile.rs`, `state.rs`, `observe.rs`, `parse.rs`,
  `policy_reg.rs`, `policy_files.rs` are new names. `ubiqx_platform::sysblock::NativeSystemShield`
  and `sysblock::helper::{HELPER_FLAG, main_if_requested, run}` are where U0 seeded them.
- `OsBackend` was reshaped (U0 allowed it): the hosts file and the state file are handled by shared
  code from the paths a back-end names; a back-end has `observe_resolver`, `observe_policies`,
  `apply_resolver(id, observed, …)`, `remove_resolver → Ok(bool)`, `apply_policies(observed,
  created, …) → created`, `remove_policies → Ok(bool)`, `elevation_tool`, `flush_dns`.
- The real `Elevator` is `elevate::RunnerElevator`, built on the `Runner`, not a type in `sys.rs`:
  that way its command line and its reading of exit codes are tested. `sys.rs` is 222 lines (the
  design says under 200); it holds no decision.
- No command has a timeout. An elevation waits for the user for as long as the prompt is open.

**The helper**
- Its own arguments have a closed alphabet (letters, digits, `-`, `_`, `,`, `=`;
  `elevate::is_helper_arg`), and the elevator refuses anything else without running a command.
  PowerShell's `-ArgumentList` joins its items without quoting, which is safe for exactly such
  words.
- `ps_single_quote` also doubles the typographic single quotes U+2018 to U+201B, which PowerShell
  reads as string delimiters.
- macOS: the helper's exit code reaches the app as the number AppleScript prints in brackets
  (`… (3)`), and -128 is `Declined`; only that number is read, never a word.
- A run writes only the tiers its own gate opens. A tier nobody wants is taken off whatever the
  gate says. A hosts block that is already there is rewritten (so a removal can take one owner's
  names out of a block the other keeps). `remove` opens nothing: it leaves the resolver and the
  policies other owners want as they are.
- An owner that asks for no tier is not kept in the state file; `apply` of a plan without any tier
  is a removal of that owner.
- A tier that fails on its first try is not recorded as wanted by the plan's owner (the page then
  shows "not applied", not drift). A tier that was applied before and fails to update stays
  recorded. After the resolver roll-back no owner has the resolver recorded.
- When a removal fails, the state file is kept with its report even if no owner remains.
- The state is recorded before anything is changed and again at the end. A helper that cannot
  write a trusted state directory (not root, a refused path) exits 4 with the machine untouched.
- `status` does the full DNS read and looks no name up. `elevate-argv` also takes `--unverified`
  and writes the tier list again from what it understood. The small binary accepts a leading
  `--shield-helper` (U9a's note): the command `elevate-argv` prints starts it that way.
- The hosts directory must be root's **and** closed to group and others (the design says "belong
  to root"). A hosts file that does not exist is created (Windows allows deleting it).
- Windows: the owner of the hosts file (Administrators or SYSTEM) is **not** checked, because that
  needs FFI beyond the two directory lookups. The path comes from `GetSystemDirectoryW`, and a
  reparse point at it is refused instead of followed.
- `hosts.error` is `write_refused` when the file or its directory is not root's (seen without
  privilege), and when the helper's last report says the write was refused and the block is not in
  the file. `plan::assess` does not read the report, so the adapter carries that one code.

**Resolver**
- Windows, full read: `servers` are what `Get-DnsClientServerAddress` reports, which includes
  servers handed out by the network. The quick read reports only servers set by hand (registry
  `NameServer`). The design's type comment says "statically configured". Consequence: on Windows
  the preview line `dns.previous` can name the router's DNS.
- Windows, quick read: one `reg.exe query … /s /v NameServer` per address family, read for the
  adapters of the last full read, which the back-end remembers (per shield instance). Before any
  full read it answers `error: unreadable`.
- DNS that could not be read is not changed (`resolver: unreadable` in the report).
- A resolver that is already in place is not set again (no second restart of systemd-resolved).

**Policies**
- Linux: a browser is "present" when an install path, its `managed` directory or its system-wide
  Flatpak directory exists. For a present browser the helper creates `policies/managed` when it is
  missing (the design: "only where the parent directory exists"; Chrome's package does not create
  it). Chromium has two `managed` directories and both get the file. A Firefox `policies.json` that
  is not byte for byte ours is `conflict`. A browser installed only as a Flatpak is `flatpak`.
- Windows: "present" is the browser's executable under `<ProgramFiles>` or its `(x86)` twin, or an
  existing policy key. A per-user install without a policy key is not seen.
- macOS: `EnterprisePoliciesEnabled` is written only when absent, listed as created only then, and
  deleted only when it is the last key of the domain. A value of `false` there is `conflict`.
- A value that was there before with our content is not listed as created and is not deleted.

**Other**
- `FrameSource`: a capture error of kind `Platform` or `NotFound` (window gone, off screen, blank)
  is `Ok(None)`; a `Permission` error is an error.
- `committed_url(has_keyboard_focus, bar_text, last_committed: Option<(url, title)>, title)`.
- `MockSystemShield` keeps a pretend machine and changes it on `apply` and `remove` the way the
  helper does, so `plan::assess` reads `Applied` afterwards. It lives in `mock_nofap.rs`.
- The test of design 11.2 (6) with a hostile environment runs in a child process (the test binary
  re-run for one ignored test with the variables set), so no other test sees the variables. On a
  Windows host it returns at once.

### Contract notes for the units that come after

**U5 (engine service)**
- `apply(plan)`: send `plan::without_gated(&plan, &gate)`. The shield answers
  `Unavailable("gated")` without a prompt for a plan with a closed tier and for a plan that asks
  for nothing while a tier is closed; `Err(Invalid)` for a name the helper would refuse, for a plan
  over the argument budget, and for an empty plan when every tier is open (call `remove` then).
  Exit codes: 0 `Applied`, 3 `Partial(only the failed tiers)`, 5 `Unavailable("gated")`, 2
  `Err(Invalid)`, anything else `Unavailable("failed")`.
- Codes this unit writes: `write_refused`, `unreadable`, `no_resolved`, `unreachable`, `failed`,
  `conflict`, `flatpak`, `appimage`, `gated`, `no_polkit_agent`. All are in
  `ubiqx_core::nofap::reason`.
- `observe`: on Windows ask for `ObserveOpts::FULL` once before the first quick read. `id` of a
  Windows interface is its interface index as text; match `previous_dns` by `id` or `name`. On
  macOS and Linux `resolver.full` is always `true`.
- After the roll-back the outcome is `Partial([resolver: unreachable])` and the state file lists no
  resolver, so `assess` gives `NotApplied`.
- `FrameSource::frame`: `Ok(None)` means skip; `Err(Permission)` means screen recording.
- `MockSystemShield::new(os)`: `calls()`, `clear_calls()`, `observation()`, `set_observation`,
  `edit_observation(|o| …)` (drift), `set_capabilities`, `set_apply_outcome(Some(..))`,
  `set_remove_outcome`, `set_canary`, `set_probe_ok`, `hold_apply() -> Sender<()>` (the next
  `apply` waits until something is sent or the sender is dropped; the call is logged first and
  nothing is locked meanwhile). `ScriptedFrameSource`: `new()`, `always(frame)`, `push(result)`,
  `set_fallback`, `calls()`, `sample_frame(seed)`, `denied()`.
- `ScriptedPlatform::peek_foreground` answers what `foreground()` last served.
- The engine's Windows and Linux exempt lists are yours; `app_id::is_self_stem` covers both
  products for the platform's enforcers.

**U7, U8 (shells, composition)**
- `NofapPorts.system`: `NativeSystemShield::native(identity.id)`, or the engine's `NoSystemShield`
  when it is `None`. `NofapPorts.frames`: **`services.frames.clone()`** (changed by the review,
  see below). Do not build a `WindowFrameSource` over `services.capturer`: on Windows and Linux
  that capturer answers with a crop of the screen when a window cannot be read.
- The standalone app: `PlatformServices::native_for(&SHIELD, Some(&data_dir))`. Pass a data
  directory: without one the secrets file falls back to ubiqX's default directory.
- `main_if_requested(std::env::args())` must be the first statement of `main` in both shells. The
  ubiqX shell does not call it yet.
- The elevated executable is the running one (`current_exe`). The polkit action's
  `org.freedesktop.policykit.exec.path` must be that installed path. A `prerm` or an NSIS hook runs
  `<executable> --shield-helper remove --owner <ubiqx|shield> --scope all`.
- From an AppImage (`APPIMAGE` set) every tier is `Unsupported { appimage }` and nothing is tried.

**U9 and the integrator (smoke, gate opening)**
- In this sandbox `status` reports systemd-resolved inactive and Chrome, Chromium and Edge present.
  A smoke run here must be `--tiers hosts` only: the resolver would answer `no_resolved` (exit 3),
  and the policy tier would write under `/etc/opt`.
- The helper matches what U9a's scripts assume (exit 0 only when every acted tier is in place; the
  block appended after the last byte; `remove --owner all --scope all` exits 0 with nothing applied
  and leaves no state directory; state directory 0755 root, state file 0644). Modes are set
  explicitly, so they do not depend on the umask of `sudo`.
- `docs/nofap/REMOVAL.md` was written from this unit's constants (`macos.rs`, `policy_reg.rs`,
  `policy_files.rs`, `windows.rs`): a change to one needs the same change there.
- `.gitattributes`: the fixtures need no line. The parsers accept both line endings and no test
  compares a fixture byte for byte with anything but itself. `reg-*.txt` and
  `powershell-adapters-*.json` carry CRLF on purpose.

### What was wrong and is fixed (commit `58e8dae`)

Each has a test in `sysblock/tests/partial.rs` (new; it failed before the fix), written against
new fault injection in the fakes (`Faults::fail`, `Faults::die_at`: a command that exits 1, and
a command at which the helper is killed).

1. **Policy values written by a run that failed or died were orphaned** (Windows registry,
   macOS preferences). `apply_policies` returned its list only on success and the state was
   written at the end, so after `reg.exe add` of Chrome's values and a failure at Firefox's,
   or a kill between two values, the state file listed nothing and `remove` (which deletes only
   listed values) left them for good. Now a back-end hands the list to `note` before its first
   write (`OsBackend::apply_policies` has that new parameter) and `converge` records it. A
   value that was there before with our content is still never listed.
2. **A policy value of ours that somebody changed was never put back.** Both back-ends skipped
   a value whose name existed, so after drift the page said `Changed`, "Restaurar" ran the
   helper, and nothing changed. A value is now skipped only when it equals ours; one that
   differs and is not ours is still a conflict and is left alone.
3. **A resolver change that failed half-way stayed on the machine with nobody recorded as
   wanting it.** macOS sets the services one by one and stopped at the first refusal; Linux
   wrote the drop-in and then failed to restart the service, leaving a file that takes effect at
   the next boot. On a first apply (no owner had the resolver) the change is now undone in the
   same run, except on an interface that already had exactly that set before. Where an owner
   already had the resolver, what is in place stays, as before.
4. **Linux: `remove` could start a stopped systemd-resolved.** `systemctl restart` starts a
   unit that is not running. The restart after deleting the drop-in now happens only when the
   look at the machine says the service is active.
5. **The frame could show another window** (Windows, Linux). `frame.rs` said "no display or
   region fallback", but the capturers it was to be built over crop the display under a window
   when the window itself cannot be read (`windows/capture.rs`, `linux/capture.rs`), and that
   crop shows whatever is in front there: a chat, a bank. The picture goes to an AI provider.
   New window-only capturers (`WindowsWindowCapturer`, `X11WindowCapturer`) refuse a display
   target and fail instead of falling back; `PlatformServices` has a new field `frames` built
   over them (macOS: the existing capturer, which has no fallback). The screenshot capturers of
   ubiqX are unchanged.
6. **The adapter parser** also reads an array that Windows PowerShell 5.1 writes as
   `{"value": [...], "Count": n}`. A server list in that shape would otherwise never read as
   the provider's set, and the tier would show `Changed` for ever.

### Read and found right

The command lines were read argument by argument against `research-dns-enforcement.md`:
`networksetup -listallnetworkservices`, `-getdnsservers <service>`, `-setdnsservers <service>
<four addresses>` and `... empty`; `defaults read|write|delete
/Library/Preferences/org.mozilla.firefox` with `EnterprisePoliciesEnabled`,
`DNSOverHTTPS__Enabled`, `DNSOverHTTPS__Locked`; `dscacheutil -flushcache`, `killall -HUP
mDNSResponder`; the three PowerShell scripts (module-qualified cmdlets, `-InterfaceIndex`,
`-ServerAddresses`, `-ResetServerAddresses`, `ConvertTo-Json -InputObject ... -Compress`);
`reg.exe query <key> /s /v NameServer`, `reg.exe query|add|delete` under
`HKLM\SOFTWARE\Policies\...` with `REG_SZ` and `REG_DWORD`; `ipconfig.exe /flushdns`;
`systemctl is-active|restart systemd-resolved`, `resolvectl flush-caches`; the policy paths
under `/etc`; `pkexec <exe> --shield-helper ...`; the `osascript` and `Start-Process -Verb
RunAs` lines. No wrong flag was found.

Injection: what reaches a command line is a network service name read from `networksetup`
(one argv item, no shell), interface indexes parsed as numbers, addresses of the compiled table
(checked as addresses again), registry names and data from constants, and the helper's own
arguments from a closed alphabet. Names from the state file are validated like a plan's. No
path comes from an argument, the state file or, on Windows, the environment.

### Still open after the review

- **Everything in the engineer's list of open points stands**, in particular: nothing ran on
  macOS or Windows; the fixtures are hand-written; the real elevation is untested end to end.
- **Windows elevation, exit code.** The script ends with `exit $p.ExitCode`. If PowerShell
  should hand back no exit code for the elevated process, `exit $null` is exit 0 and the app
  would read `Applied`; the verify pass that follows would then show the truth. I did not
  change the script, because I cannot run it. The smoke job's step 5 shows which it is.
- **One network service that refuses the resolver blocks the tier on that Mac.** The first
  apply is undone as a whole (fix 3). Whether any service of a real Mac refuses
  `-setdnsservers` is unknown.
- **X11 without a compositing manager:** `GetImage` of a window returns the screen's pixels
  where another window covers it, so a covering window can still be in the frame there. Under a
  compositing manager (GNOME, KDE, most desktops) the window's own content is read.
- **xcap on Windows**: whether its window capture itself reads the screen for some windows was
  not checked; only our own fallback was removed.
- **After a failed first apply of the policies** the values that were written stay until the
  next helper run in which nobody wants the tier (they are recorded, so that run deletes them).
  They are not rolled back in the failing run.
- **`reset_targets` includes switched-off interfaces** (`ubiqx-nofap`, not this unit): a
  disabled macOS service the user had set to the provider's addresses by hand is reset by a
  `remove`.
- **SELinux label of the hosts file.** The write is a new file renamed over `/etc/hosts`, so on
  Fedora and the like the file gets the default label of `/etc` instead of its own
  (`net_conf_t`). Reading it should still be allowed everywhere; nobody has checked, and
  `restorecon /etc/hosts` puts the label back.
- **A state file of a newer version** (`v` other than 1) reads as "no state": an older helper
  then forgets the other owner. Only matters once a version 2 exists.
- **CI** of the review commits: see the reviewer's report; run 264 is the last one read to its
  end.
