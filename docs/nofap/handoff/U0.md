### Deviations from the design

- Display name: DISPLAY_NAME = "NoFap" (orchestrator decision 1), not "Escudo". The seeded apps/nofap/src-tauri/tauri.conf.json uses productName and window title "NoFap" and sets mainBinaryName "ubiqx-shield" so the executable keeps the machine id.
- NofapChange uses struct variants everywhere, because serde's internal tag (`kind`) cannot carry a bool, Option or String newtype: SetHosts { on }, SetPolicies { on }, SetHostsUserSites { on }, SetVision { on }, SetResolver { resolver }, SetPrefs { prefs }, SetValues { text }, SetPlans { plans }. Wire form is flat: { "kind": "set_hosts", "on": true }.
- PendingView carries `kind: ChangeKind` (new enum, same strings as the change tag), `ready`, `remaining_secs`, `expires_at`, and NOT the change itself: an AddAllow change has a `host` field and NofapStatus must have none. The page reads the full change from NofapView.config.pending. PendingChange gained `ready_since` (needed for the 24-hour expiry).
- NofapStatus gained `hosts_waiting` and `extras_left_out` (the two counts the copy needs). VisionState is Off { reason: VisionOff } | On | Degraded { until }; VisionOff is its own enum and has `not_onboarded`, which the design's table did not name. GuardState::Limited carries a GuardLimit enum.
- Tagged wire forms chosen: TierState, GuardState, VisionState and TierCapability use tag `state`; ApplyOutcome uses tag `outcome` with content `detail`; NofapEvent tag `type`; UserEvent tag `event`; ChangeOutcome is externally tagged ({ applied } | { pending }). TierReport is { tier, ok, reason }.
- FrameSource::frame returns CoreResult<Option<Frame>>; Ok(None) is 'no usable frame' (window gone, near-uniform capture). The design had CoreResult<Frame>.
- NofapCard gained `note_key` (second line, e.g. vision.added) and `auto_close_secs`. CardAction gained `request_exception` ("Pedir exceção") and `later` ("Agora não").
- NofapView: `config` is a separate ConfigView type without `internal` (the salt cannot reach the wire by construction); added `product` and `ai: AiReadiness`; `today` is { blocks, checks }; `cost_line` is { month_usd, month_checks, cap_usd }. SystemCapabilities has `os` and `unverified` (tiers opened by the tester override).
- EnableOptions gained `self_use` (the wizard tick; the engine should refuse without it) and `vision_consent: Option<ConsentArgs>` so the wizard's last button is one request. `export` returns ExportResult { path }. SupportView.progress is { window_days, days, streak: Option, after_reset }.
- NofapSite is deliberately not Serialize/Deserialize (a learned site cannot be written anywhere but the database); host_key is [u8; 16].
- SystemObservation, SystemState, OwnerWants, HostsStamp, PolicyCreated, PolicyObservation, InterfaceDns, BrowserFamily, Os, Tier live in ubiqx_core::nofap (the design left their shape open). The hosts file travels in the observation as lossy UTF-8 text; hosts::splice and hosts::inspect take bytes.

### Deviations from the design

- SystemShield::observe takes `opts: ObserveOpts { full, canary, probe }` (design 2.5: no argument). Reason: the design gives the cadence rules to the verify pass (full Windows read at apply, page open and every 30 min; canary only while the block is applied; probe while the resolver is applied) and says the adapter holds no decision; a parameterless call could express none of that. `ObserveOpts::default()` is the cheapest look (QUICK); `ObserveOpts::FULL` is the full DNS read without lookups. Seeded `OsBackend::observe` got a `full: bool` argument.
- PlannedChange.text_key is one of `ubiqx_core::nofap::preview::LINES` (11 keys: preview.hosts_add {n}, preview.hosts_update {n}, preview.hosts_remove, hosts.readable, preview.resolver_set {resolver}, dns.previous {servers}, preview.resolver_reset, preview.policies_set {browsers}, policies.disclosure, preview.policies_conflict {browsers}, preview.policies_remove). The design left the keys open; eight of them are new i18n keys the copy bank does not have (they fall under the 'about 70 short keys written by the frontend unit').
- Reason codes are a closed list, `ubiqx_core::nofap::reason::ALL` (write_refused, unreadable, appimage, no_resolved, unreachable, flatpak, conflict, gated, not_built, unsupported_os, no_system_layer, no_polkit_agent, failed). The types still carry a String (no wire change); the design named some codes and left the set open.

- LogNofapPresenter writes no log line at all (the design only names the type). A line per card is a log of hits, which 4.4 forbids at any level.

### Open points

- CI on three systems is unverified for this unit. In particular the macOS app job runs `cargo test --workspace`, which now builds the standalone shell (tauri-build with a frontendDist that does not exist yet); that has never completed in CI and cannot be cross-checked here. Someone has to let one run finish on a commit at or after 2ae7ddd.
- No IPC command exists for the design's 'Verificar agora' (2.3 mentions the button, the table of 7.8 and the copy bank do not). With ObserveOpts, U5 can do the full read when `view` is called (the page opening). If a separate button is wanted, it needs a new `cmd` through the integrator.
- A stored NofapConfig that fails to parse (for example a pending change of a kind written by a newer build: one unknown `kind` fails the whole document) must not be read as 'default', because the default is 'module off'. NofapRepo::load_config documents the default only for a missing row; U3 should return an error for an unreadable row and U5 should surface it rather than run disabled. Not fixed here: it is behaviour of U3/U5.
- plan::assess is pure per observation, and an observation that was not asked for the canary has `canary: None`. The caller (U5) has to put its last canary answer there, or Issue::HostsNotHonoured comes and goes between lookups. I documented this on `assess` in plan.rs; U2 and U5 need to honour it.
- resources.json is an empty list. U2 must fill the five entries of 5.7; until then the release-mode test `resources_verified` would pass vacuously.
- heuristics.rs (U1) carries the design's word lists unchanged, and several block-grade substrings match ordinary names: `putas` in disputas/computas, `nudes` in denudes, `peladas` in apeladas, `porn` in the French town Pornichet, `xxx` in roman numerals; and the brand stem `cam4` folds to `cama` (camara, camarote, pijama). U0 flagged cam4 and e-hentai; the substrings are not in 3.6's trap list and U1 should test them.
- Exhaustiveness is compile-forced only for fieldless enums (through the new test). For enums with data (TierState, GuardState, VisionState, NofapEvent, UserEvent, ApplyOutcome, NofapCommand::NAMES) the tests only count the variants present in the samples; a new variant needs the sample updated by hand.
