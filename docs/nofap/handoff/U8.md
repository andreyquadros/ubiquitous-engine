Written by the engineer. Where this file and the code differ, the code wins.

## Engineer

U8 is done: the standalone product (the owner's "+1 novo produto a parte") is a second Tauri shell
over `NofapApp` and a second Vite entry. A person who wants no productivity tracking installs only

### How it is wired

- **Start**: `NofapApp::start(NofapAppConfig { data_dir: app_data_dir, notifier, presenter,
  update_sink, system_layer: true, build, update_feed_url, .. })` inside `block_on`, then the
  state, the tray, a tray refresh, and the main window unless `--minimized` after onboarding.
  `main` hands `--shield-helper` runs to the helper first (U0), so `system_layer: true` is sound.
- **Commands**: `nofap` → `NofapApp::handle` on the blocking pool (it refuses a consent for the
  managed provider); `nofap_host` → `NofapApp::handle_host`, and a `settings_set` relabels the
  tray; `quit_app` → `quit`. Errors are `{ code, message }` like ubiqX's.
- **Quit** (tray "Sair", the tray's confirmed quit, the window's button): `service.on_quit()` on
  the blocking pool, `stop_loops().await`, `exit(0)` (U7 review's advice). `RunEvent::Exit`
  (logout) stops the loops and releases the lock; an `ExitRequested` without a code is refused.
- **Tray**: "Abrir"; while the module is on, the status line (`tray.status_on`) and "Preciso de
  um respiro" (`#/support`); "Verificar atualizações" (a known or newly found build opens its
  https download, otherwise the settings); "Sair". While the module is on, "Sair" is a submenu:
  the true quit sentence (disabled), "Manter aberto", "Sair". The menu is rebuilt whole under a
  lock on every status event and settings write.
- **Frontend**: `HostGate` reads `settings_get` (language applied unless `?lang=`) and sends a
  first start to `/welcome`. `Welcome`: language and what the app is not; then the optional AI key;
  its last button writes `onboarding_done` and lands on `/`, which is `NofapPage`, i.e. the
  module's consent wizard while protection is off. `NofapPage` gets `{ autostart, openSettings }`;
  autostart is the operating system's login item (the autostart plugin), read and written there.
  `/support`, `/lists`, `/help` open the page's tabs. `NofapSettings`: language, launch at login,
  provider (Anthropic, OpenAI, xAI only), key (save checks with the vendor; remove stops the check),
  vision model from the vendor's list, permissions (only those that apply), updates (automatic
  check, check now, install and reopen through the updater plugin, the download otherwise), data
  (to the help tab), about with name, version, identifier and the third-party notices
  (`THIRD-PARTY-NOTICES`, embedded as text).
- **Outside Tauri** every host call goes to `hostMock.ts`, which keeps the module's mock told of
  the provider and the AI readiness. `?nofap=<scenario>` starts past the welcome; `?host=fresh`
  and `?host=onboarded` choose.

### Deviations from the design

- **A third command, `quit_app`.** Design 6.3 wants the exits in the standalone window too, and a
  tray icon is not always visible (GNOME without an indicator extension, no tray host). The
  window's rail has "Sair", which asks first with the true sentence (`nofap.quit.confirm_system` or
  `confirm_none`, from the same rule as the engine's `system_applied`) and "Manter aberto" as the
  primary button, whether the module is on or off. The tray quits at once while the module is off,
  as ubiqX's does.
- **No quit dialog window; a submenu in the tray**, as in ubiqX (no dialog plugin). The status line
  and "Preciso de um respiro" are there only while the module is on.
- **Launch at login is the operating system's login item**, read and written through the
  autostart plugin from the page: `NofapHostCommand` has no `launch_at_login`, and the settings
  row's `launch_at_login` (default `true`) is not used by this product.
- **`vite --mode nofap`**, not `VITE_PRODUCT=nofap`: an environment assignment in a package script
  does not run in Windows' shell.
- **The built page is `dist-nofap/index.html`.** The naming test forbids the source name outside
  the display keys and `build` of `tauri.conf.json`, so the main window cannot have
  `url: "index.nofap.html"`. Vite renames the page; the dev server answers `/` with the entry.
- **ubiqX's mock never enters `dist-nofap`.** The module's `ipc.ts` falls back to `lib/mock`
  outside Tauri; in the nofap build every import of `src/lib/mock.ts` resolves to
  `src/nofap-app/hostMock.ts` (`vite.config.ts`, mirrored by `graph.test.ts`).
- **`server.fs.allow` takes the repository root** (both modes): Vite refuses `?raw` of a file
  outside the allowed roots, and a single file cannot be allowed because the check also sees the
  `?raw` suffix. The about box reads `THIRD-PARTY-NOTICES` that way; a test reads the standalone
  `tauri.conf.json`.
- **The build commands of `tauri.conf.json` were wrong** (U0's seed): Tauri runs them in
  `apps/nofap`, so `../../desktop` pointed outside the repository. They are `pnpm --dir ../desktop
  dev:nofap` / `build:nofap` now, checked with `tauri dev`. `frontendDist` stays
  `../../desktop/dist-nofap` (it is relative to `tauri.conf.json`).
- **`devUrl` `http://localhost:1430`**: without it `generate_context!` needs `dist-nofap` in every
  build, and the macOS CI job's `cargo test --workspace` compiles this shell without building the
  frontend.
- **The notices are the repository's `THIRD-PARTY-NOTICES`**, embedded in the frontend; `about`
  carries none (U7).
- **The rail has two items** (the module, its settings): the page already has its tabs, so
  `/support`, `/lists` and `/help` are routes that open them.
- **The shell is three files** (`app.rs`, `card.rs`, `tray.rs`, 630 lines in all, no logic):
  section 13 limits `app.rs` alone.
- **Bundle and installers** (beyond U0's minimum): active, the same targets, macOS minimum and
  Windows and Linux settings as ubiqX, `shortDescription` the display name, the updater with
  ubiqX's public key (the same signing key), the two uninstall hooks with `--owner shield`.
- `Cargo.toml` and `build.rs` are unchanged.

## Final review

Two findings of the last round of skeptics on the shells, CI and documents, each confirmed by at
least two of three. Both concern U7's ubiqX shell as much as this one, so both shells changed the
same way (U7's hand-off points here). The packaging files cannot run here, so the new test
`crates/ubiqx-app/tests/packaging.rs` reads them: it failed on the files as they were (both
tests below) and passes now.

1. **A newer `-setup.exe` run by hand took the system tiers off** (important). The reinstall page
   of Tauri's NSIS template (CLI 2.11.4, read from the bundled template) pre-selects "uninstall
   before installing" on an upgrade and runs the installed uninstaller with `/P` at most and
   `_?=<install folder>`, never `/UPDATE` (that page is skipped in update mode). The hooks of both
   shells checked only `$UpdateMode`, so they ran `--shield-helper remove` behind a UAC prompt in
   the middle of an install, without the commitment delay, and the helper then cleared the state
   file. Now `packaging/nsis-hooks.nsh` of both shells keeps the system changes when
   `$UpdateMode = 1`, or `$EXEDIR` is `$INSTDIR`, or `$EXEFILE` is `uninstall.exe`: the
   uninstaller runs in place only when another setup started it with `_?=`; a real uninstall
   (Settings, Control Panel, or `uninstall.exe` opened by hand) runs from the temporary copy NSIS
   makes first. The kept case prints one detail line. Test:
   `the_uninstall_hook_removes_the_system_changes_only_on_a_real_uninstall` runs each hook through
   a small evaluator of the LogicLib subset it uses (it refuses any other construct; its own
   test is `the_hook_evaluator_reads_logiclib_chains_as_nsis_does`) for six ways of starting the
   uninstaller. Both hooks compile with `makensis -WX` 3.09 inside a stub installer (done here, not
   in CI). `REMOVAL.md` (Windows row) and checklist item 15 (a new row) describe the hand-run
