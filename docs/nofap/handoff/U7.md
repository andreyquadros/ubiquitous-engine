### How it is wired

- **ubiqX** (`App::start`): `NofapPorts { system, frames: platform.frames, detector, presenter,
  sink, repo: store, shared_dir, tuning: Tuning::default() }`. `system` is
  `NativeSystemShield::native(UBIQX.id)` and `shared_dir` is `<local data>/ubiqx-shield` only when
  `AppConfig.nofap_system` is set **and** the platform is native; otherwise `NoSystemShield` and
  no lock. The detector is `LlmExplicitDetector` over the routing client (remote backend), a fake
  that always answers "none" (fake backend), or none.
- **The CLI** builds `AppConfig` with `..AppConfig::default()`: `nofap_system` is `false`, so the
  CLI never gets the system layer (its executable does not handle `--shield-helper`) and never
  takes the primary lock. The module is off by default, so its passes touch no platform port.
- **Standalone** (`NofapApp::start`): the store `shield.db` in the data directory;
  `PlatformServices::native_for(&SHIELD, Some(&data_dir))` (decision 25); `RemoteClients` with
  the routing client; `LlmExplicitDetector`; `nofap_system_layer(&SHIELD, system_layer)`;
  `StandaloneEnv` over the settings row and the secret store; `NofapService::new(NofapDeps::
  assemble(...))` with `identity: &SHIELD`, `usage: store`, `export_dir: <data>/exports`; an
  `UpdateChecker` on `SHIELD.feed_url`, `for_product(SHIELD.feed_product)`. No `Engine`.
- **The shell's command** forwards `{ cmd, args }` to `ubiqx_engine::nofap::ipc::handle` on the
  blocking pool and maps `CoreError` to the existing `IpcError` (`invalid`, `not_found`,
  `storage`, ...).
- **Events**: every `NofapEvent` is emitted as the Tauri event `nofap`. A `status` event also
  refreshes the tray items, from a task of its own (the sink never calls back into the service
  on the emitting thread).
- **Card window**: label `shield-card`, route `index.html#/nofap-card?id=<id>` (the id keeps only
  `[A-Za-z0-9_-]`), title "UBI", 420 px wide, no decorations, always on top, on all workspaces,
  no taskbar entry, built hidden and shown without focus, centred 24 px under the top of the
  monitor under the cursor. A second card re-points the same window (hash change) and shows it
  again. The opening height follows `cardSize` of `labels.ts` (132, 160, 200, 220, 560); the page
  then asks for its own size, which the capability allows. `dismiss` is not overridden: the page
  closes itself on `card_closed`.
- **Logger**: `hyper_util`, `hyper`, `reqwest`, `rustls` at `warn` (hand-off U3, decision 25).
- **Quit**: "Sair" (module off) and the confirmed quit (module on) both run `quit_app`:
  `nofap().on_quit()` on the blocking pool, then `EngineHandle::shutdown`, then `exit(0)`.
- **Single instance**: registered first; a second launch shows the main window of the first.

### Deviations from the design

- **`AppConfig.nofap_system`** (not in 7.7). The system layer elevates the running executable,
  and only a shell whose `main` calls `main_if_requested` can be that executable. Default
  `false`, so the CLI and tests can never apply anything; the ubiqX shell sets it.
- **The standalone loops are written in `nofap_app.rs`** instead of spawning
  `ubiqx_engine::nofap::run_guard_loop` / `run_verify_loop`: those take a
  `tokio_util::sync::CancellationToken`, and `ubiqx-app` has no `tokio-util` dependency (only the
  integrator edits manifests). The two loops do the same (first tick skipped, the pass on the
  blocking pool, the check spawned and not awaited, the primary lock given up at the end) with a
  `tokio::sync::watch` stop signal. **For the integrator:** with `tokio-util` added to
  `ubiqx-app`, they can be replaced by the engine's.
- **`NofapAppConfig`** has replaceable pieces for tests and demos (`detector`, `frames`, `clock`,
  `tuning`, `loops`, `update_sink`) next to the fields of `AppConfig`; `system_layer` is the
  standalone's `nofap_system`. It has no `ubi_api_base`: the managed provider is not in this
  product (8.5). Its `RemoteClients` still builds the Ubi client (on the default base) so the
  router is total; `StandaloneEnv` answers `licence_required` for that provider and
  `settings_set`, `api_key_set` and `models` refuse it.
- **No quit dialog window.** The shell has no dialog plugin (and adding one is a dependency).
  While the module is on, the tray's "Sair do ubiqX" becomes a submenu with the true sentence
  (`quit.confirm_system` or `quit.confirm_none`) as a disabled item, then "Manter aberto" and
  "Sair". "Manter aberto" only closes the menu. With the module off, "Sair" is ubiqX's own item.
- **"Não pausa o {name}" is an item, not a tooltip**: Tauri's menu items have no tooltip. While
  the module is on, a disabled item with that text sits under the pause and private-mode items.
- **"Preciso de um respiro"** opens the main window at `#/nofap?tab=support` (hand-off U6: the
  card window has no panic entry route; the page's panic button is in its header).
- **The tray status line** is `tray.status_on` ("{name}: ligado"), shown with "Preciso de um
  respiro" under "Abrir ubiqX" while the module is on; nothing of the module is in the tray
  while it is off.
- **The NSIS hook uses `ExecShellWait "runas"`** (ShellExecute with the `runas` verb, the same
  elevation `Start-Process -Verb RunAs` uses) instead of starting PowerShell. It has no exit
  code, so a declined prompt is not reported on the last page; the hook prints one detail line
  before the prompt. The hook removes this product's wants only (`--owner ubiqx`).
- **The deb hook finds the executable with `dpkg-query -L "$DPKG_MAINTSCRIPT_PACKAGE"`** (the
  file under `/usr/bin/`) instead of a fixed path, because the installed name of ubiqX's binary is
  still unverified (checklist item 25). It acts only on `remove`, never on `upgrade`, and never
  fails the removal.
- `Info.plist` is unchanged: nothing of this unit needs a key there.
- `NofapApp` is not `Clone`; dropping it stops its loops.

### Found and fixed

1. **The card window never changed size on Linux** (`apps/desktop/src-tauri/src/nofap.rs`). It was
   built with `resizable(false)`; on GTK a window that is not resizable keeps its content's
   requested size, so every card stayed 420 x 200: the discreet card (132) and the support flow
   after "Abrir apoio" (560) included, whatever the shell's `set_size` or the page's `setSize`
   asked (both returned success). The card is now built resizable; it has no decorations, and
   the next card sets the size again if a person drags an edge. Checked in the app: 132 for the
   test card, 560 after "Abrir apoio" was clicked in the card.
2. **Tray refreshes could race** (`nofap_tray.rs`). Every status event starts a refresh on a
   thread of its own, and each one read `enabled()` and `quit_dialog()` before taking the lock:
   a refresh that read "on" just before the module was switched off could apply after the one
   that read "off", leaving the module's items and the quit confirmation in the tray of a
   module that is off. The read is now under the same lock as the apply. No shell test exists
   for this (the shell crate has none).
3. **The card window could take focus and hide itself** (`capabilities/shield-card.json`). The
   page calls `close()` and `setSize()` and has a drag region, nothing else; `set-focus` and
   `hide` are gone (checked from inside the card: both refused, `nofap` still allowed). This
   departs from the list in design 5.3 on purpose: the card must never take focus. A new
   composition test pins the permissions and reads `NofapCard.tsx` so that a later call to
   `setFocus`, `hide`, `show` or `setAlwaysOnTop` from the page fails the test instead of
   failing silently in the window.
4. **The standalone accepted a consent for "IA do Ubi"** (`nofap_app.rs`). The fixture's
   `consent_vision { provider: ubi, managed: true }` succeeded and was stored. `NofapApp::handle`
   now refuses `consent_vision` and `enable` when they consent to the managed provider (design
   8.5); test `the_managed_provider_cannot_be_consented_to` (it fails with the guard removed).
5. **The zero-rows test ignored every reply.** All 41 requests of `commands.json` could have
   failed and the test would still pass. Each reply is now read as the type its command
   documents (7.8), the refusals are pinned to the seven this state calls for (`enable` while
   on, the two symbolic site ids, `pending-1` twice, `system_remove` and `reset` while on, and
   now `consent_vision` for the managed provider), every table of the schema outside the
   module's, `settings`, `kv` and `ai_usage` is checked empty (not only a named list, so a table
   added later is covered), `categories` keeps its seeded rows, and `ai_usage` holds nothing but
   `nofap_vision`. A new test, `the_standalone_database_has_the_schema_of_ubiqx`, compares
   `user_version` and every object of `sqlite_master` of `shield.db` with the database ubiqX's
   own `App::start` creates: the same.
6. **The loop test proved nothing, then failed under load** (decision 31). It slept 50 ms with a
   2 s interval. Its first rewrite in this review slept fixed margins; the failure the
   integrator saw at line 705 ("a guard pass acted after shutdown") came from this reviewer's
   mutation run (shutdown made a no-op) in the shared tree, but the fixed margins were a real
   weakness. Now `NofapApp` keeps its loops' tasks and `stop_loops().await` returns once all have
   ended; the three `select!` are `biased` towards the stop, so a tick due at the same moment as a
   shutdown no longer starts one more pass. The test waits for passes that act on a listed site
   (a fixed clock moved two hours per site, so each is an episode of its own and counts), then
   for the stop acknowledgement; the deadlines (60 s) only bound a broken loop. The whole crate
   passed 5 times in a row under six busy loops plus a release build; with `shutdown` made a
   no-op (in a copy of the tree) the test fails.
7. A doc comment of `build_ai` had slid onto `validate_api_key` (`crates/ubiqx-app/src/lib.rs`).
8. `zbus` is held at `warn` in the shell's logger: with the single-instance plugin it wrote one
   `info` line per second launch (seen in the run).

### Still open

- **Focus on macOS and Windows** (unverifiable here). tao 0.35.3's `set_visible(true)` calls
  `makeKeyAndOrderFront` on macOS (`platform_impl/macos/window.rs:670`), so every `show()` makes
  the card the key window (keyboard focus moves only when ubiqX is the active app). On Windows,
  `focused(false)` sets `MARKER_DONT_FOCUS` once and the first show clears it
  (`platform_impl/windows/window_state.rs:329`): from the second card on, `show()` is
  `ShowWindow(SW_SHOW)`, which activates the window. Design 5.3 wants the card shown without
  taking focus. A candidate, untested: `set_focusable(false)` before `show()` and
  `set_focusable(true)` after (macOS reads the flag in `canBecomeKeyWindow`, Windows maps it to
  `WS_EX_NOACTIVATE`). Needs a person on each system (checklist).
- **Every window can call every ubiqX command.** Tauri 2 checks app commands against the ACL only
  when `build.rs` declares them (`tauri_build::Attributes::app_manifest`); this one does not, so
  the card window (like the intervention window before it) may call `delete_all_data` and the
  rest. Only the app's own pages load there (CSP, local assets), so the risk is small. Restricting
  it means editing `apps/desktop/src-tauri/build.rs`, which U7 does not own: for the integrator.
- **The MSI has no uninstall hook.** `bundle.targets` builds `msi` as well as `nsis`; design 2.7
  names only the NSIS hook. An MSI uninstall leaves what was applied to the system. For U9
  (`REMOVAL.md`) or the integrator (a WiX fragment, or dropping the MSI).
- **A hand-run helper prints nothing on Windows release builds**: `main.rs` keeps
  `windows_subsystem = "windows"`, so `ubiqx.exe --shield-helper status|remove` from an elevated
  prompt has an exit code but no console output. For U9 (`REMOVAL.md`).
- **The engine's own loops** (`ubiqx_engine::nofap::run_guard_loop`, `run_verify_loop`, U5) have
  the same unbiased `select!` between the cancel token and a due tick. For U5's owner.
- Single instance on Linux needs a D-Bus session bus. Launched by mistake without one in this
  review, a second instance started and ran a second engine on the same database for 20 s until
  stopped. Rare on a desktop session; noted.
- `ubiqx track` (CLI) takes no primary lock (`nofap_system` is false, so `shared_dir` is `None`):
  with the module on in the database and the desktop app running, both processes would enforce.
  The same two-engines-on-one-database condition existed before the module.
- The engineer's open points stand: the tray was not looked at (no tray host under Xvfb), the
  uninstall hooks are unverified, nothing of the shell ran on macOS or Windows.
